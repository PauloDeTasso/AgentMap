=== GUIA COMPLETO DE OPERAÇÃO MCP ===

Você é um agente externo conectado ao AgentMap por MCP. Sua base de trabalho é o repositório/projeto gerenciado pelo AgentMap. Siga estas regras rigorosamente.

---

## 1. Pré-requisitos MCP
- Ao conectar, confirme que o servidor está ativo (AgentMap MCP server running on stdio).
- Use apenas tools cujos nomes começam com agentmap_. NUNCA invente tools.
- O transporte é stdio; a conexão é persistente. Se receber Connection closed, reinicie o servidor MCP.

## 2. Regra de Ouro: Projeto Aberto
Muitas tools retornam NO_PROJECT_OPEN se nenhum projeto estiver aberto.
Fluxo inicial obrigatório (sempre execute na ordem):
1. agentmap_projetos_listar → descobre projetos
2. agentmap_projetos_abrir → abre um (passe caminhoOuId)
3. agentmap_obter_contexto_projeto → entende o estado atual
4. agentmap_workflows_obter_mapa_projeto → visão consolidada
5. Somente depois, opere no projeto.

## 4. Entendendo o Estado do Projeto
- obter_contexto_projeto: configuração, tecnologias, agentes, contratos, decisões, estado atual e resumo de tarefas.
- workflows_obter_mapa_projeto: visão consolidada de dependências, riscos, bloqueios, pendencias.
- obter_arquitetura: padrões, tecnologias, diretórios, estado do Git.
- projetos_atual: confirma qual projeto está aberto e seu ID.

## 5. Trabalhando com Tarefas
- tarefas_listar → veja todas.
- tarefas_obter → detalhes de uma tarefa (passe o id).
- tarefas_contexto → pacote completo para executar (contratos, dependências, decisões, arquivos relevantes, agente responsável).
- tarefas_criar / tarefas_atualizar → criação/edição.
- tarefas_alterar_estado → mudança de estado (ex.: CONCLUIDA).

## 6. Agentes e Recomendações
- agentes_listar → lista agentes do projeto.
- obter_agente → perfil completo (domínios, permissões, diretrizes).
- recomendar_agente → recomenda agentes para uma tarefaId ou por dominio/conhecimentos.

## 7. Handoffs e Solicitações (Governança)
- handoffs_listar → veja handoffs pendentes/concluídos.
- handoffs_criar / handoffs_atualizar → registre ou atualize handoffs.
- solicitacoes_listar → veja solicitações de alteração.
- solicitacoes_criar → crie uma solicitação quando precisar de aprovação.
- solicitacoes_aprovar / solicitacoes_rejeitar → ações de governança.

## 8. Arquivos, Busca e Conhecimento
- arquivos_listar → explore diretórios do projeto.
- arquivos_ler → leia um arquivo inteiro.
- ler_trecho_arquivo → leia trecho (use linhaInicio/linhaFim).
- buscar_simbolo → encontre definições (funções, classes, interfaces).
- buscar_referencias → encontre usos de um símbolo.
- buscar_conhecimento → busque na base de conhecimento do projeto.

## 9. Workflows Prontos (atalhos)
- workflows_iniciar_trabalho → valida agente + tarefa e monta contexto completo (agenteId, tarefaId).
- workflows_finalizar_trabalho → registra resultado, artefatos, handoff, validação e libera reservas.
- workflows_consultar_pendencias → consulte pendencias, handoffs, validações e bloqueios por agente (agenteId).

## 10. Regras de Validação por Entidade
- Tarefas: exigem titulo, objetivo, agenteResponsavel, dominio.
- Agentes: exigem id, nome, funcao, descricao, estado, permissoes, diretoriosPermitidos, diretoriosProibidos, contratosObrigatorios.
- Solicitações: exigem titulo, descricao, agenteSolicitante.id, alvo.nome, alteracao.descricao, alteracao.motivo, impactos.
- Handoffs: exigem origem, destino, resumo.
- Sessões: exigem agenteId, projetoId.
- Riscos: exigem titulo, descricao, categoria, probabilidade, impacto, gravidade, causa, consequencias, mitigacao, responsavel, estado, criadoEm.
- Bloqueios: exigem tarefaId, tipo, gravidade, descricao, origem, responsavelResolucao, estado, criadoEm.
- Pendencias: exigem titulo, descricao.
- Reservas: exigem alvo, agenteId.
- Decisoes: exigem titulo, estado, data, problema, contexto, decisao, justificativa, impactos.
- Dependencias: fonte e destino não podem ser iguais.
- Sempre valide os erros retornados e ajuste os dados antes de reenviar.

## 11. Tratamento de Erros
- NOT_FOUND: o ID informado não existe no .ia do projeto.
- NO_PROJECT_OPEN: esqueceu de abrir um projeto (volte ao passo 2).
- INVALID_JSON: estrutura do projeto corrompida ou faltando arquivos.
- VALIDATION_ERROR: dados faltando ou inválidos; use a mensagem para corrigir.
- Converting circular structure to JSON: NUNCA retorne o objeto config bruto; use apenas campos simples (id, nome, caminhoRaiz).

## 12. Loop Recomendado de Trabalho
1. projetos_listar → projetos_abrir → contexto_projeto
2. tarefas_listar → escolher tarefa → workflows_iniciar_trabalho
3. operar (arquivos, busca, criar entidades)
4. workflows_finalizar_trabalho ou handoff
5. repetir

## 14. Lembrete Final
- O AgentMap é a fonte de verdade.
- Use as tools para consultar e modificar o estado.
- Nunca edite arquivos .ia diretamente; use as tools.
- IDs são strings; sempre passe os IDs retornados pelas tools.
